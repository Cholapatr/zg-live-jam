# ZG Live Jam

แอปเว็บสำหรับงาน outing บริษัท ให้แขก ~80 คนเสนอ/โหวตเพลง นักดนตรีตอบรับ และแอดมินจัดคิว Next Show List พร้อมคอร์ดเพลง ใช้งานผ่านมือถือ ไม่ต้องติดตั้งแอป

มี 3 หน้า:
- **หน้าแขก** (`/index.html`) — เสนอเพลงใหม่ / โหวต (อยากฟัง, อยากร้องเอง, ขอให้คนอื่นร้อง) / ดูคิวถัดไปพร้อมคอร์ด
- **หน้านักดนตรี** (`/musician.html`) — ดู Request List เรียงตามโหวต แล้วกดตอบรับ (อยากเล่นมาก / เล่นได้ / ลองดู / เล่นไม่ได้ / ไม่ระบุ)
- **หน้าแอดมิน** (`/admin.html`) — ล็อกอินด้วย PIN ดูข้อมูลโหวต+การตอบรับของนักดนตรีประกอบการตัดสินใจ แล้วจัดลำดับ Next Show List เองได้อิสระ

ทุกหน้าอัปเดตแบบเรียลไทม์ (ผ่าน Socket.IO) — แขกคนอื่นโหวต ทุกคนเห็นทันที

## Login (ตัวเลือกเสริม) + ⭐ Favourite List

ไม่ล็อกอินก็ใช้งานได้ปกติทุกอย่าง — login ใช้เฉพาะปลดล็อกฟีเจอร์ **⭐ Favourite List** (เลือกเพลงเก็บไว้ล่วงหน้าก่อนงาน แล้วกดขอเพลงจริงในงานได้เร็วๆ) เข้าสู่ระบบได้ด้วย Microsoft 365, Google หรือ LINE (เลือกอันใดอันหนึ่ง) ไม่มีระบบรหัสผ่านของแอปเอง

ต้องตั้งค่า Client ID/Secret ของแต่ละ provider ก่อนถึงจะเห็นปุ่ม login — ดูขั้นตอนทั้งหมดที่ [`LOGIN-SETUP.md`](./LOGIN-SETUP.md) และตัวอย่างตัวแปรที่ [`.env.example`](./.env.example)

## รันทดสอบในเครื่องตัวเอง

ต้องมี [Node.js](https://nodejs.org) (v18 ขึ้นไป) ติดตั้งไว้ก่อน

```
cd zg-live-jam
npm install
npm start
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:3000` — PIN แอดมินตั้งต้นคือ `1999` (เปลี่ยนได้ด้วย environment variable `ADMIN_PIN`)

## Deploy ให้ใช้งานได้จริงในวันงาน (ออนไลน์ผ่านเน็ตมือถือได้ ไม่ต้องพึ่ง WiFi รีสอร์ต)

ใช้ [Render.com](https://render.com) — ฟรี ไม่ต้องผูกบัตรเครดิต ทำผ่านหน้าเว็บล้วน ไม่ต้องใช้คำสั่ง

**ขั้นตอน:**

1. **สร้างที่เก็บโค้ดบน GitHub** (ถ้ายังไม่มีบัญชี สมัครฟรีที่ github.com)
   - กด "New repository" ตั้งชื่อ เช่น `zg-live-jam` → Create repository
   - กด "uploading an existing file" แล้วลากไฟล์/โฟลเดอร์ทั้งหมดในโฟลเดอร์ `zg-live-jam` นี้ขึ้นไป (ยกเว้น `node_modules` ถ้ามี) → Commit changes

2. **สมัคร Render.com** ด้วยอีเมลหรือบัญชี GitHub (ฟรี)

3. ที่ Render กด **New +** → **Web Service** → เลือก "Build and deploy from a Git repository" → เชื่อมกับ repo `zg-live-jam` ที่เพิ่งอัปโหลด

4. ตั้งค่า:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
   - เพิ่ม **Environment Variable**: `ADMIN_PIN` = ใส่รหัส 4-6 หลักที่ต้องการ (ค่าเริ่มต้นถ้าไม่ตั้งคือ `1999`)
   - ถ้าจะเปิดระบบ login/⭐ Favourite List ด้วย เพิ่มตัวแปรตาม [`LOGIN-SETUP.md`](./LOGIN-SETUP.md) (อย่างน้อยต้องมี `APP_BASE_URL` เป็นลิงก์ของ service นี้ และ `SESSION_SECRET`)

5. กด **Create Web Service** รอ 2-3 นาที จะได้ลิงก์ เช่น `https://zg-live-jam.onrender.com`

6. แจกลิงก์:
   - แขกทุกคน: `https://zg-live-jam.onrender.com`
   - นักดนตรี: `https://zg-live-jam.onrender.com/musician.html`
   - แอดมิน/ทีมงาน: `https://zg-live-jam.onrender.com/admin.html` (ใช้ PIN ที่ตั้งไว้)
   - แนะนำทำ QR code จากลิงก์แขก (เช่นที่ qr-code-generator.com) แล้วปริ้นแปะโต๊ะ

**หมายเหตุ:** แผน Free ของ Render จะ "หลับ" ถ้าไม่มีคนเข้าใช้เกิน 15 นาที ครั้งแรกที่มีคนเข้าอาจช้าราว 30-50 วินาที แนะนำเปิดลิงก์ทิ้งไว้ในเครื่องทีมงานก่อนงานเริ่มเพื่อ "ปลุก" เซิร์ฟเวอร์ไว้ล่วงหน้า

## เกี่ยวกับคอร์ดเพลง (dochord)

หน้า "คิวถัดไป" จะฝังหน้าค้นหาเพลงจาก dochord.com ไว้ในกรอบให้เลยตามชื่อเพลง+ศิลปิน ถ้าบางเพลงกรอบไม่ขึ้น (เว็บบางหน้าอาจกันการฝัง) จะมีลิงก์ "เปิด dochord ในแท็บใหม่" ให้กดแทนเสมอ

## ข้อมูลจะหายไหม

ข้อมูลเก็บเป็นไฟล์ในเซิร์ฟเวอร์ ถ้าไม่ deploy โค้ดใหม่ระหว่างงาน ข้อมูลจะอยู่ครบตลอดคืน แนะนำอย่ากด redeploy ระหว่างงานกำลังเล่นอยู่
